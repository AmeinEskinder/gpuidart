# Dart, GPUIX/Solid and GPUI Shell: three foreground repetitions

**All 36 planned measurements completed.** The series contains three runs of each workload in each implementation, plus four retained incomplete attempts. All 3,148 delivered update clicks in completed runs passed application checks.

The repeated results support a specific tradeoff. Dart used fewer private bytes than this Bun/Solid implementation, while its idle working set was higher. Shell had the lowest readings on both memory measures. Dart's single-cell CPU observations were lower than Solid's in all three runs. Idle and burst CPU ranges overlapped, and no scroll run maintained every scheduled input slot. Presentation remains unmeasured.

The production architecture, application fixtures and driver were unchanged during capture. The separate [Rust/Dart series and corrected partial follow-up](rust-dart-20260925.md) were not extended.

## Method and evidence

Each workload ran in a fresh process for ten seconds after a three-second warmup and pointer settling. Implementation order rotated:

| Repetition | Order |
| --- | --- |
| 0 | Dart, Solid, Shell |
| 1 | Solid, Shell, Dart |
| 2 | Shell, Dart, Solid |

The capture resumed across foreground interruptions. Incomplete attempts remain in the record. Completed observations were retained regardless of cadence; no completed result was rerun to improve its timing or correctness.

All fixtures used 100,000 records, an 860 by 650 logical viewport, 32-pixel rows and three 200-pixel columns. All 36 completed runs passed checks for DPI 120, a 1075 by 812 physical client area, recorded executable/driver hashes, disabled input tracing, expected final application state and input sent_ms values before the ten-second cutoff.

The machine has an i7-11850H with 8 cores and 16 logical processors, about 32 GiB RAM, Windows 11 Pro 26200 and a Balanced power plan. Resume inventories recorded external power and unchanged graphics drivers/display settings. The desktop is 1920 by 1200; WMI reports 59 Hz. The rendering adapter was not recorded. Background desktop activity, CPU frequency and thermal conditions were not isolated.

Versions are Dart 3.13.4, Rust 1.98.1, GPUI Kit 21622a70efd25219d26aa459164878c4da9e39f8, GPUI Shell 0.6.5, GPUI pre 0.3.6, GPUIX native/Solid 0.10.0, Solid 1.9.15 and Bun 1.4.0. The exact QuickJS revisions and dependency pins are in [artifacts.json](artifacts.json).

## Process CPU

CPU is process CPU time divided by elapsed time, with one logical core equal to 100%. Values are the median [minimum, maximum] of three completed runs. This table retains observations with skipped driver slots.

| Workload | Dart | Solid | Shell |
| --- | ---: | ---: | ---: |
| Idle | 0.78 [0.62, 1.25] | 1.87 [1.09, 2.81] | 1.56 [0.94, 1.87] |
| Scroll | 20.16 [16.25, 24.37] | 28.75 [28.44, 32.65] | 20.00 [18.12, 22.34] |
| One cell at 5 Hz | 3.75 [2.81, 3.75] | 4.53 [4.22, 5.16] | 2.81 [2.66, 3.75] |
| Eight cells at 30 Hz | 15.15 [12.03, 17.50] | 16.87 [14.06, 18.28] | 13.59 [13.59, 15.00] |

For single-cell updates, all three implementations delivered all 50 scheduled clicks. Dart's CPU readings were below Solid's in all three runs, with non-overlapping observed ranges. The difference between medians is 0.78 percentage points of one core. This supports a CPU benefit for this specific workload and fixture.

Idle and burst ranges overlap. Dart's burst CPU was lower than Solid's in two repetitions and higher in the other, so the lower aggregate median does not establish a consistent burst advantage.

Dart's observed scrolling CPU was below Solid's, but every scroll observation missed scheduled input slots. The fixtures also performed different drawing and virtualization work. These observations do not establish a comparison at the exact planned 60 Hz cadence.

Dart and Shell's CPU ranges overlap in every workload. This series does not establish a general CPU advantage over Shell.

## Startup, payload and comparison limits

Idle process-launch-to-HWND medians were 462 ms for Dart, 305 ms for Solid and 277 ms for Shell. Their observed ranges were 392 to 535 ms, 278 to 444 ms and 251 to 357 ms, respectively. These are three samples each and do not measure startup to a usable or displayed UI.

The earlier explicit copied packages were 29.48 MiB for Dart, 107.20 MiB for Solid and 58.70 MiB for Shell. Those copies are separate artifacts from this run's hashed binaries. Full installed size and clean-machine dependency closure remain unverified.

Dart uses GPUI Kit's DataTable. Shell uses uniform_list with QuickJS visible-row callbacks. Solid uses its native virtual list and an explicit 32-row window. Fonts, data, dimensions and requested input rates match, but selection, column controls, scrollbars, overscan, drawing and update behavior differ. Results compare these complete implementations, including their data storage and runtime packaging. They do not isolate the language runtime.

No ETW capture was requested; the previously recorded access restriction is unchanged. Response-frame correlation, input-to-present latency, displayed frame-time percentiles and missed display frames remain unmeasured.

## Engineering conclusion

The repeated measurements support lower private-byte usage for GPUI-Dart than this Bun/Solid fixture and a CPU benefit in the tested single-cell workload. They do not support a blanket lower-memory or lower-CPU claim. Shell's memory readings remain lower, and Dart has no established general CPU advantage over Shell.

All planned captures are complete. The architecture remains frozen. Comparable presentation evidence is still needed before making a responsiveness claim.
